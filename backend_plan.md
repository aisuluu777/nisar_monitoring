# План бэкенда: прототип за 5 часов

Фронтенд делает другой специалист. Моя зона: `pipeline/`, `analytics/`, `api/`, БД, ИИ-слой, Docker. Контракт для фронта: OpenAPI на `/docs`, выдаётся в первый час.

## Решения для прототипа (подтверждены заказчиком)
- **Охват: вся Киргизия.** Сразу несколько районов: по одному-два самых больших района в каждой из 7 областей (Баткен, Джалал-Абад, Иссык-Куль, Нарын, Ош, Талас, Чуй). Это расширяет ТЗ (там пилот на одном районе), поэтому в ТЗ нужна правка. Каждый район — запись в `config/districts.yaml` (id, область, название, bbox). Границы пока приблизительные bbox; точные полигоны заказчик даст позже.
- **Размер ячейки зависит от района.** Большие районы дают десятки тысяч ячеек. Для прототипа ячейка 2–5 км, настраивается; в `pipeline` стоит лимит числа ячеек на район.
- **БД: PostgreSQL + PostGIS** в Docker Compose, SQLAlchemy + GeoAlchemy2, миграции Alembic. Геометрия настоящая, фильтры по району через `ST_Intersects`.
- **Данные NASA.** Токен Earthdata будет, его даёт заказчик, он кладётся только в `.env`. Источники работают через интерфейс `SignalSource`:
  - `AsfGunwSource` (NISAR через asf_search) и `Hyp3Source` — реальные данные, сначала проверка доступности по районам;
  - `NasaPowerSource` — реальные суточные осадки;
  - `SyntheticSource` — запасной вариант, если реальных данных на район нет. Все такие записи помечаются `synthetic=true` в паспорте и в `/sources`.
  Реальная обработка интерферограмм тяжёлая. Для прототипа нужен хотя бы один район с реальным рядом, остальные могут идти на запасном источнике. Это решается после проверки токена (этап 0, 30 мин).
- **Статусы** — правила из ТЗ (раздел 6): серый, зелёный, жёлтый, красный. ML не используется.
- **ИИ.** Слой готовится полностью: `LLMProvider` (абстракция), шаблонный резерв, проверка чисел, запретные фразы, чат по функциям для чтения. Провайдер и ключ заказчик даст позже (`LLM_PROVIDER`, `LLM_API_KEY` в `.env`); пока включён шаблонный режим.
- **Авторизация.** JWT для сотрудников и API-ключи для исследователей. Роли: `public`, `admin_district`, `emercom`, `researcher`, `sysadmin`. Роль администрации привязана к району или области.

## Ледники (добавлено)
- Отдельная таблица `glaciers` (полигон, RGI-id, площадь, высоты, район). Сигналы и статусы хранятся в общих `observations`, `baselines`, `statuses` с полем `entity_type` (`cell` или `glacier`).
- Источники: контуры — сейчас OpenStreetMap `natural=glacier` (ODbL, через Overpass; GLIMS WFS не нашёлся), далее RGI 7 / GLIMS; скорость ITS_LIVE, снежный покров MODIS/VIIRS; ICESat-2 по возможности. Доступность проверяется в блоке 0:00–0:30; без реальных данных — `SyntheticSource` с пометкой.
- Аналитика: сезонная норма скорости и снега, робастный z; сильное ускорение относительно нормы — жёлтый, устойчивое два цикла подряд плюс подтверждающий сигнал — красный; мало данных — серый.
- API: `GET /glaciers`, `GET /glaciers/{id}`, `/glaciers/{id}/series`; ледники входят в сводку района.
- Вне прототипа: ледниковые озёра и риск прорыва (GLOF).

```
backend/
  app/

    config.py          .env, district.yaml
    db.py, models.py   SQLAlchemy: cells, products, observations, baselines,
                       statuses, decisions, bulletins, users, api_keys
    schemas.py         Pydantic
    auth.py            JWT, ключи, зависимости по ролям
    routers/           districts, cells, decisions, bulletins, assistant, export, sources, health
  pipeline/
    __main__.py        python -m pipeline run --district <id>
    grid.py            сетка ячеек
    sources/           base.py, synthetic.py, nasa_power.py
    run.py             идемпотентный цикл: данные → observations → analytics → bulletins
  analytics/
    baseline.py        сезонная медиана + MAD
    scoring.py         робастный z, сравнение с соседями
    clusters.py        кластеры соседних ячеек (scipy.ndimage.label)
    status.py          правила статусов + список причин с числами
  ai/
    facts.py           пакет фактов (JSON)
    templates.py       шаблонные тексты (3 режима, ru/ky)
    validator.py       сверка чисел, запретные фразы, обязательные блоки
    provider.py        LLMProvider (+ заглушка)
    assistant.py       чат через функции только для чтения
  tests/
  Dockerfile, docker-compose.yml, .env.example, README.md
```

## Если время поджимает (порядок отсечения)
1. Парсинг кыргызского и режим исследователя (оставляем ru, простой и специалист).
2. `assistant/ask` — оставляем только шаблонный ответ.
3. Выгрузки Parquet и GeoTIFF — оставляем CSV и GeoJSON.
4. Уведомления Telegram и email — только заглушка и журнал.

Нельзя отсекать: паспорта продуктов, серый статус, список причин с числами, роли на сервере, шаблонный бюллетень с блоком «Чего мы не знаем».

## Критерии приёмки прототипа
- `docker compose up`, затем `python -m pipeline run` — на карте API есть ячейки с четырьмя статусами.
- Второй запуск конвейера не меняет БД.
- Администрация района видит только свой район; публичный уровень получает только агрегаты.
- Каждый бюллетень содержит три блока, числа сверены с пакетом фактов, «безопасно» и «будет оползень» в тексте не проходят.
- Решение «подтверждено / ложная тревога» пишется в журнал без возможности правки.
- Источники с `synthetic=true` явно помечены в паспортах и в `/sources`.

## Что нужно от заказчика (не блокирует старт)
- Токен Earthdata: положить в `backend/.env` как `EARTHDATA_TOKEN`, не присылать в чат.
- Список районов или подтверждение выбора больших районов по областям.
- Точные границы районов (полигоны).
- Ключ и провайдер LLM (позже).
